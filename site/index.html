From an issue to a merged branch

Write the task down, give the agent the context, let several run at once, and read every change before it lands on your base branch.

1 plan

Your tracker is a folder of markdown files

Issues live in your project as plain files. That is why an agent can work them: picking one up, changing its status, commenting and filing a follow-up are all just edits.

  • Dispatch an issue to an agent and it moves to In progress
  • Open a PR and it moves to In review. Merge and it closes
  • Comments, links, attachments and due dates, all in the file
2 context

Notes your agents can actually read

A wiki that lives in your repo, with wikilinks, backlinks, tags, an outline and a quick switcher, plus a journal with daily notes and a weekly note built from what actually happened.

  • Hand a note to an agent and watch the page update as it writes
  • Put an agent in the side panel of the note you are working on
  • Keep a notes-only workspace with no code in it at all
3 run

Six agents, six branches, no collisions

Every run opens in its own git worktree: a second checkout of the same repo on its own branch. Agents working the same project never touch each other's files. Watch them all in a grid, or pull one full size when it needs you.

  • Different agent CLIs on the same repo at the same time
  • Plain terminals alongside, in the project checkout, when you want one
  • Desktop alerts when an agent finishes, stalls on a question or hits a conflict
4 review

Read the diff before you trust it

Per-hunk diffs, commit, history, branches and stash for whichever worktree you are standing in. Review a pull request, open one, merge it, and resolve the conflicts when two agents reach for the same lines.

  • Per-run diffs, so you review one agent's work at a time
  • Comment on a diff and send it straight back to the agent

No account. No vendor backend. No telemetry.

Agency does no first-party data collection, and there is no server of ours for it to talk to. The agents are third party and talk to their own providers, the same as when you run them in a terminal.

The one request Agency makes on its own is a check against GitHub for a newer release. It sends no identifiers, and one switch in Settings turns it off.

Questions

What is Agency?

A desktop app for macOS and Linux that runs AI coding agents in parallel. It launches the agent CLIs you already have, gives each run its own git worktree and branch, and lets you watch, review and merge them in one window.

Is Agency free?

Yes. Agency is free and open source under the Apache-2.0 licence, with no paid tier and no account. You pay only for the agents themselves, through whatever plan or API key each one already uses.

Which coding agents does it work with?

Eleven are built in: Claude Code, Codex, Cursor, Copilot CLI, OpenCode, Gemini CLI, Kimi Code, Crush, Hermes, Pi and DeepSeek Harness. Any other agent you can start from a command line runs too.

How do several agents work on one repo without conflicts?

Each run gets a git worktree: a separate checkout of the same repository, on its own branch, in its own folder. Agents never share a working tree, so they cannot overwrite each other's files. Their work meets only when you merge it, and Agency helps you resolve any conflicts then.

Does Agency send my code anywhere?

Agency does no first-party data collection: no analytics, no telemetry, no account. The agents it launches are third party and send your prompts and code to their own providers, exactly as they do in a terminal. Agency's only request of its own is an update check against GitHub, which you can turn off.

Why not just run agents in tmux?

You can, and plenty of people do, with a worktree per pane. Agency does that bookkeeping for you: it cuts the worktree and branch, tracks which agent is working, waiting or done, shows each run's diff, and merges and cleans up after. The by-hand version is a handful of git and tmux commands, if that is all you need.

Does it run on Windows?

Not yet. Agency runs on macOS 11 or later on Apple Silicon, and on Linux (x86_64 and arm64) as a .deb, .rpm or AppImage. Windows is planned, with no date yet.

Can an agent change things without my say?

Agency never raises an agent's permissions behind your back. Each agent runs with the permission mode you choose for it, in its own worktree, and nothing reaches your base branch until you merge it.
